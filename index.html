01 / Selected work

One project, built all the way to production.

Chessify is a chess learning and playing platform: piece guides, a training mode, a bot you can play, and live 1v1 games over an invite link. I designed the data model, wrote the API, built the interface, wrote the engine, and deployed it.

ChessifyLiveSolo · 2026 Source
01EngineA chess engine written from scratch. It searches ahead with alpha-beta pruning, remembers positions it has already seen, and tries the most promising moves first. It runs on a background thread in the browser, so a 2.5-second think never freezes the board.
02APISign in with a cookie or play as a guest, with hashed passwords and limits on repeated sign-in attempts. Every move is checked on the server — turn, legality, checkmate, stalemate, repetition and the fifty-move rule are never trusted to the client.
03RealtimeEach game has its own live channel that sends the full game state on every change, with a steady heartbeat so connections are not cut. A move appears on both boards without refreshing or polling.
04DataOne record per game, with the move list and evaluation history stored inside it. Storage switches between a local file and the database with a single setting, and a re-runnable script moved the existing data across without duplicating anything.
05AdminUsage statistics, user management, an audit trail of every sensitive action, and export of recorded games for analysis.
06DeliveryTwo services deployed from one config file — the API and the website — with cache headers, a rewrite so requests to /api reach the server, and secrets kept in environment settings.

03 / How it fits together

One request, three hops.

Every move goes to the API, gets checked, gets stored, and comes back to both players through a stream.

Layer 01 · Client

Browser

The client never trusts itself.

  • The board and training mode
  • Runs the bot locally
  • Listens for live game updates
Layer 02 · Server

Server

Every move is sent here and checked.

  • Sign-in and guest play
  • Game clocks and increments
  • Audit log of sensitive actions
Layer 03 · Storage

Database

Checked moves are stored, then streamed to both players.

  • One record per game
  • Move history kept inside it
  • Users and bot games
Layer 04 · Delivery

Hosting

Two services from one config file.

  • API and website hosted apart
  • Cached for speed
  • Requests to /api forwarded to the server

The bot is not on the server. It runs in the visitor’s browser, so playing it costs the server nothing — the server only records the finished game.
